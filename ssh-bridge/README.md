# Meow SSH Bridge

浏览器扩展不能直接打开 SSH 的 TCP 连接，所以真实 SSH 模式需要在本机运行这个很小的桥接进程。扩展只连接 `127.0.0.1`，桥接再用 `ssh2` 登录你的服务器。

有两种启动方式，任选一种：

| 方式 | 适合 | 是否显示命令行窗口 |
| --- | --- | --- |
| `MeowSshBridge.exe`（推荐） | 日常使用 | 不显示，常驻托盘/任务栏 |
| `start.bat` | 开发调试 | 显示命令行窗口 |

## 方式一：桌面版 exe（推荐）

> **安装位置很重要**：请把 exe 放在 **C 盘**（推荐 `%LOCALAPPDATA%\MeowSshBridge`、桌面或 `Program Files`）。
> 放在 `F:` 等映射盘/工作区盘上运行时，程序会被系统以**低完整性级别**启动，此时 Windows 会直接拒绝它注册托盘图标（`Shell_NotifyIcon` 返回 `ERROR_ACCESS_DENIED / 5`），表现就是“看不到托盘图标”。程序只能自动降级为任务栏模式。

1. 双击 `MeowSshBridge.exe`（建议放在 C 盘，例如 `%LOCALAPPDATA%\MeowSshBridge`）。
2. 程序**不会弹窗**，在通知区域（右下角托盘）出现一个红色猫图标，桥接已经在后台监听 `ws://127.0.0.1:8765`。
3. **单击（或双击）托盘图标**打开窗口，可以看到：
   - 运行状态（运行中 / 未运行）、当前地址；
   - 访问令牌（点“复制”，粘贴到扩展里）；
   - 实时运行日志（成功为绿色、警告为橙色、错误为红色）；
   - 端口修改（“应用并重启”）、重启桥接、清空日志、打开数据目录。
4. 在 Meow 大日历 → SSH → 右上角插头按钮，填入地址和令牌，点“测试并保存”。

窗口行为：

- 点窗口右上角的关闭按钮 **不会退出程序**：托盘模式隐藏到托盘，托盘模式下可以用托盘图标再打开；
- 想彻底退出：托盘图标右键 → “退出”，或窗口里的“退出”按钮；
- 程序重复双击时不会启动第二份，只会把已有窗口叫出来。

### 两种运行模式（自动选择）

启动时会先探测系统是否允许本进程注册托盘图标（`Shell_NotifyIcon`）：

| 模式 | 触发条件 | 表现 |
| --- | --- | --- |
| 托盘模式 | 探测成功（exe 在 C 盘、正常用户权限） | 启动不显示窗口，只留托盘图标；关闭按钮 = 隐藏到托盘 |
| 任务栏模式 | 探测失败（典型是 exe 放在 F: 等工作区盘，以低完整性级别运行） | 启动即以最小化形式留在任务栏；关闭按钮 = 最小化到任务栏 |

任务栏模式是为了兜底：有些环境（提权启动、安全软件、远程会话托管）会让 `Shell_NotifyIcon` 直接返回 `ERROR_ACCESS_DENIED`，此时托盘图标根本不会被创建，如果窗口还默认隐藏就打不开界面了。探测结果会写进 `data\app.log`（“托盘图标探测：可用/被系统拒绝”）；在任务栏模式下，窗口日志里也会有一条橙色提示说明原因。

若想恢复托盘图标：把 exe 复制到 C 盘后重新运行；确认不是以管理员身份启动（托盘注册不需要提权）。

数据目录（令牌、指纹记录、日志、端口配置）按以下顺序选择第一个可写的目录：

1. exe 同目录下的 `data`（便携模式，换机器时整个文件夹拷走即可）；
2. `%LOCALAPPDATA%\MeowSshBridge`；
3. `%TEMP%\MeowSshBridge`。

如果数据目录不可写（例如被安全软件限制），窗口里会给出提示，令牌仍然从运行日志里读出并显示，可以照常复制使用。

## 方式二：命令行（start.bat）

1. 安装 Node.js 18 或更高版本。
2. 双击 `start.bat`，或在当前目录运行：

   ```powershell
   npm install
   npm start
   ```

3. 终端会打印：

   ```text
   地址:  ws://127.0.0.1:8765
   令牌:  xxxxxxxxxxxxxxxxxxxxxxxx
   ```

两种方式共用同一份 `bridge-core.js`，协议、令牌和主机指纹校验完全一致，扩展端不需要做任何区分。

## 说明

- 桥接只监听 `127.0.0.1`，局域网其他机器无法直接连接。
- 访问令牌会保存在数据目录的 `.bridge-token`，也可以设置环境变量 `MEOW_SSH_TOKEN` 固定令牌。
- 密码只保存在扩展的 `chrome.storage.local` 和桥接进程内存中，不会写入日志。
- 首次连接某个 `host:port` 时会把服务器主机公钥指纹写入 `known_hosts.json`；以后指纹变化会拒绝连接。确认服务器确实更换了密钥后，删除对应条目再重连。
- 默认端口是 `8765`，可用 `MEOW_SSH_PORT` 修改（exe 版也可以在窗口里改，会记到数据目录的 `config.txt`）；扩展里的地址要同步修改。
- 真实 SSH 支持交互式 shell、`cd`、Tab 补全、方向键、`sudo`、`vim` 等依赖 PTY 的操作，具体取决于远端服务器配置。

## 构建 exe

需要 Node.js 18+ 和 Windows 自带的 .NET Framework 4.x（`csc.exe`）。

```powershell
cd ssh-bridge\app
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

脚本会依次完成：

1. `esbuild` 把 `bridge-core.js` + `ws` + `ssh2` 打包成一个 CJS 文件；
2. 用 Node SEA 把该文件注入 `node.exe`，得到单文件 `bridge.exe`；
3. 自检 `bridge.exe` 能否正常监听；
4. 用 `csc.exe` 编译托盘宿主，并把 `bridge.exe` 与图标作为嵌入资源打进去。

产物：

- `dist\MeowSshBridge.exe`：托盘版单文件程序（约 90 MB，内含 Node 运行时，目标机器无需安装 Node）；
- `dist\bridge.exe`：单文件桥接本体，方便命令行/脚本直接调用。

参数：`-SkipSea` 复用已有的 `build\bridge.exe` 只重编托盘程序；`-OutDir <dir>` 指定输出目录。

## 停止

- exe 版：托盘图标右键 → “退出”，或窗口里的“退出”按钮（会先清理 SSH 会话再释放端口）。
- 命令行版：在桥接窗口按 `Ctrl+C`。

## 常见问题

- **双击 exe 没反应 / 界面像卡死**：先看数据目录里的 `app.log`，它记录了每次启动、子进程 pid 和退出原因。常见原因：
  - 之前退出不干净，留了个 `bridge.exe` 占着 8765。新版宿主会把子进程放进作业对象（KILL_ON_JOB_CLOSE），宿主被强杀/崩溃时子进程会被系统一并结束；子进程也会在宿主消失后自行退出，不会再留孤儿。
  - 端口被别的程序占用：程序会自动弹出日志窗口并显示原因，把端口改成 `8766` 点“应用并重启”即可。
  - 程序其实已经在托盘运行（图标被收进 `^` 里），重复双击只会唤起已有窗口，不会启动第二份。旧版本在这种情况下会静默退出、看起来像没启动，新版会直接弹出窗口或给出提示。
- **连接被拒绝**：确认托盘图标还在、桥接状态是“运行中”，地址和令牌完全一致。
- **重启桥接后无法重连 / `Connection lost before handshake`**：新版桥接会等待旧实例释放端口，扩展也会在握手前断线时自动重试一次。如果仍然出现，请检查服务器是否限制了同一 IP 的同时连接数，或端口转发是否有旧连接残留。
- **认证失败**：确认服务器允许密码登录；如果只允许密钥登录，当前版本需要先配置服务器或使用模拟模式。
- **主机指纹不一致**：服务器可能重装或更换了 SSH 密钥。核对指纹后删除数据目录 `known_hosts.json` 中对应 `host:port` 条目。
- **端口占用**：在窗口里把端口改成 `8766` 后点“应用并重启”，并在扩展里填写 `ws://127.0.0.1:8766`；命令行版可设置 `MEOW_SSH_PORT=8766` 后重新启动。
- **托盘图标不见了**：先看 `data\app.log` 里的“托盘图标探测”一行。
  - 显示“被系统拒绝”= 程序运行在低完整性级别（最常见原因：exe 还在 F: 等工作区盘上）。把 exe 复制到 C 盘再运行即可；临时可点任务栏上的窗口按钮使用。
  - 显示“可用”但看不到图标 = Windows 11 把新图标默认放进了“隐藏的图标”（`^`）里。从 `^` 里把猫图标拖到托盘上即可固定；也可以在“设置 → 个性化 → 任务栏 → 其他系统托盘图标”里把它打开。
